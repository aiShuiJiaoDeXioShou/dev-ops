# DevOps Web 响应式与触控

沿用本仓库的页面模式、Token 与共享控件。先读通用 UI 实现与验收规则，再定位实际页面的布局容器和断点。[DSH UI 技能](../dsh-client-ui-ux/SKILL.md) · [页面布局与响应式](../../../docs/ui-guidelines.md#layout) · [页面模式](../../../docs/design/patterns.md#6-响应式)

## 布局与内容

- 页面模式在 1280px 起使用完整双栏或三栏，768–1279px 收窄侧栏并允许覆盖式详情，低于 768px 使用单列、表单单列。先核对目标路由实际断点。390px 宽度下主操作可达，消息和状态可读，页面无意外重叠、裁切或横向滚动。宽表格、确需保留列对齐的代码等使用各自容器滚动。
- 依次考虑释放可用宽度、换行、重排操作区，再考虑截断、图标化或把次要操作收进「更多」。保持主操作、选中态、错误和关键状态可见，使用既有字号与可点尺寸。
- 页面标题优先完整显示，必要时将操作区移到下一行。卡片标题优先自然换行。标签、页签、选择器等空间有限时可省略次要文案，完整内容要能通过详情、展开或其他键盘和触控可达的方式查看。附件长名遵循组件的中间省略规则。[组件选择](../../../docs/design/components.md)

## 触控、键盘与焦点

- 用宽度查询控制重排，使用 `(hover: hover)` 管理纯悬停样式，使用 `(pointer: coarse)` 校验粗指针下的目标和输入尺寸。指针事件打开悬停内容时跳过触摸事件。触屏和键盘都能直接操作或通过显式入口找到原先悬停显示的操作。选中、展开、按下与 `:focus-visible` 状态独立于 hover。
- 图标化操作优先选择含义清楚的图标，提供 `aria-label`。触控目标至少 32×32px，移动端优先 44×44px。悬浮提示可给鼠标和键盘补充名称或快捷键。触屏点图标直接执行，必要说明通过可点击、可聚焦的帮助入口打开。[图标控件](../dsh-client-ui-ux/references/icons.md#图标控件) · [可访问性](../../../docs/design/interactions.md#9-可访问性)
- 尽量重排同一控件以保留焦点和草稿。若原控件在新布局中消失，把焦点移到可见的同类入口。关闭菜单、抽屉或弹窗时检查焦点归还。检查滚动容器和视口边缘是否遮挡浮层。
- 窄屏重排时避免无意聚焦文本字段并弹出软键盘。弹窗初始焦点遵照该流程的控件规则。验证软键盘出现后当前字段、错误提示及提交动作可达。若 iOS Safari 聚焦紧凑字段时放大页面，在共享控件层复用字号样式，让受影响场景的输入字号达到 16px。[控件、键盘与浮层](../../../docs/ui-guidelines.md#controls)

## 浏览器验收

按主技能完成 1440×1000 和 390×844 截图。用长标题、长标签和有内容的列表检查实际页面，涉及断点时再检查两侧。涉及输入或触控时验证打开和关闭浮层、旋转或改宽后的焦点、软键盘和草稿。设备模拟只能覆盖已模拟的行为，交付时标出未核对的真机或浏览器表现。
