# V0.8 CLI 业务覆盖

V0.8 让研发人员、测试人员、管理员和脚本通过 `devops` 完成现有 Web 的业务操作。服务器以同一套业务规则处理 CLI 与 Web 请求。V0.7 的值守与外部通知按原路线交付。

[逐操作覆盖](coverage.md)收录本版新增或扩展的命令。已有命令和全局参数参见 [CLI 手册](../../apps/cli/README.md)。

## 1. 业务范围

| 批次 | 交付内容 |
| --- | --- |
| 流水线与交付 | 工作流、运行、日志和产物，执行节点，产物目录、运行版本、外部审核与发布 |
| 项目与事项 | 项目筛选、晴雨表、服务、模板、回收站和恢复，事项排期、附件、人选与证据 |
| 协作与智能体 | 会话、消息、分支、工作标签、接力控制，任务和验收，智能体、模型、MCP、记忆、提示模板、团队上下文、用量与预算、Skills |
| 团队与平台 | 团队资料、个人 GitHub 绑定状态、项目写工具调用记录、凭据、环境变量和储存桶 |

账号自助、个人 API Token 管理、第三方账号登录与授权、凭据明文、项目删除和文件清理由 Web 承载。GitHub 个人绑定及模型订阅从 Web 发起。CLI 查询绑定状态或连接状态。代码文件在线编辑与第三方页面跳转由原渠道承载。现有服务与仓库关联、构建更正等 API 独有操作另行排期。

## 2. 授权与调用

个人 API Token 的权限由请求当时的账号角色和资源归属决定。新版服务端允许已有 Token 执行其账号有权进行的任务转交、验收与退回，群聊接力控制，Skills 查询与管理，模型 API Key 连接创建与连接启停，项目回收站查询与恢复，储存桶管理与个人 GitHub 绑定状态查询。浏览器会话继续使用原有业务权限。服务端在这些入口拒绝内部 Bot 委托。

结构化写入通过 `--file <path>` 提交 JSON。复杂筛选使用 `--query-file <path>`，字段沿用命令帮助列出的 OpenAPI 请求契约。使用 `-` 时从标准输入读取。含凭据值的请求使用标准输入，标准输入一次只能承载 Token 或业务数据。带版本的写入沿用当前业务乐观锁，版本冲突由调用方读取最新数据后处理。

流水线等待区分成功、失败、取消和超时。日志及会话事件跟踪持续输出文本，分页读取支持 `--json`。附件与产物下载校验 SHA-256 后写入新文件。节点创建和轮换的一次性 Token 写入 `--token-out` 指定的文件，文件权限为 `0600`。

## 3. 验收

- 使用同一 PostgreSQL 数据库和两种凭据验证 CLI 与 Web 数据一致。场景覆盖需求排期、附件与多人提测、Bug 回归、流水线运行和产物、运行版本确认、智能体发消息与任务验收。
- 验证任务转交、已签发 Token 的权限变化、跨团队拒绝、平台管理员权限、撤销与过期。登录会话专用接口须拒绝仅提供 Token 的请求。
- 验证失败退出码、输出脱敏、分页无重复、版本冲突、超时和中断、文件完整性与覆盖保护。
- 发布前运行 `pnpm check` 和 `pnpm --dir apps/server test:db`。服务端先部署，随后发布配套 CLI。现有 Token 和命令继续可用。
