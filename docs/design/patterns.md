# 页面模式

## 1. 列表 + 详情

适用：项目、需求、Bug、代码引用等。

结构：

```
.page-head
  h1 + 统计/说明 + 主操作
.catalog
  .filters
    .segments / select / .search
  .table-wrap > .table 或 .project-grid
  .details（右侧详情，必要时 portal 到详情宿主）
```

要求：

- 筛选条件写入 URL；刷新/返回可恢复。
- 打开详情后筛选条件保持；修改导致不匹配时记录移出但详情保留。
- 关闭详情恢复列表滚动位置。
- 列表状态：loading、error、empty、no-match、read-only。
- 行操作不放在标题里造成意外跳转；行内有明确按钮。

参考实现：

- `apps/web/src/features/projects/ui/project-list.tsx`
- `apps/web/src/features/requirements/ui/requirement-list.tsx`
- `apps/web/src/features/bugs/ui/bug-list.tsx`

## 2. 详情面板

适用：需求、Bug、项目。

结构：

```
.details
  .detail-top：标题 + 编辑/展开/关闭
  .detail-scroll：属性、描述、关联、讨论/活动
  .composer：输入 + 发送
```

要求：

- 默认宽度 375px 左右，小屏改为覆盖式。
- 编辑与关闭按钮必须有 aria-label。
- 未保存修改时关闭要确认。
- 评论/活动分页失败时保留已加载内容并提供重试。

## 3. 表单弹窗

适用：创建项目、邀请成员、需求/Bug 动作。

结构：

```
Dialog
  DialogHeader：标题 + 说明
  form
    字段组
    field-error
    DialogFooter：取消 + 主操作
```

要求：

- 打开时聚焦第一个字段或标题。
- ESC/遮罩关闭遵循业务：有未保存内容时确认。
- 主操作 loading 时禁止重复提交。
- 失败时弹窗不关闭，输入保留。
- 成功后关闭并将焦点归还触发按钮。

## 4. 认证页

适用：登录、接受邀请、找回密码、重置密码。

当前视觉基线：

- 分栏：左侧品牌/特色，右侧认证表单。
- 背景使用 `--background` / 认证页专用类；不新写裸色值。
- 表单控件使用 shared Input/Button；错误提示可见、可读。
- 页面宽度 1440/390 下均不能横向滚动。

要求：

- 登录失败文案不区分“邮箱不存在/密码错误”时，按安全策略统一提示。
- 提交中禁用按钮；支持 Enter 提交。
- 邀请 token 失效/已使用时给出明确恢复入口。
- 不展示不存在的 SSO 入口。

## 5. 设置页

适用：团队、项目设置、仓库连接。

结构：

```
.page-head / .work-page-head
.settings-section
  .section-heading
  .field / .table / .empty
```

要求：

- 仅管理员可见的入口在前端隐藏，服务端仍需鉴权。
- 变更保存后给出 toast；失败保留表单。
- 破坏性操作使用二次确认。
- 空状态提供下一步操作。

## 6. 响应式

| 断点 | 要求 |
| --- | --- |
| ≥ 1280 | 双栏/三栏完整布局 |
| 768–1279 | 侧栏收窄，详情面板可覆盖 |
| < 768 | 单列；表单单列；表格允许横向滚动；触控目标 ≥ 32px |

截图检查尺寸：

- 桌面：1440×1000
- 移动：390×844

## 能力页（Skills / AGENTS.md 模板）

- 页面结构：`.page-head.skills-header` 放页签与主操作，内容区直接使用 `.catalog`，不再套 `.content`，避免页签与工具栏之间出现多余留白。
- 页签：`技能库 / AGENTS.md 模板` 使用图标 + 文案，选中态沿用原型下划线，不使用全局链接 hover 下划线。
- 列表：分类胶囊 + 搜索 + 卡片网格；超过一页时分页并保留 URL 中的搜索、分类与页码；空目录用 Bot 吉祥物与下一步操作，无匹配用搜索图标与清除条件。
- 模板卡片展示分类、版本、正文摘要与项目选用状态（已选用数量/未选用）；选用状态来自服务端列表数据，不由前端推断。
- 详情：纯文本预览、复制/下载、版本与活动、项目选用/取消选用；快照只读、仅团队成员可访问、不自动过期。
- 阶段 B 的 Bot 入口在 M07 交付前隐藏或显示“尚未开放”，不显示空壳。


## 运维 / 变更计划（V0.4b）

- 入口：主导航“运维”进入团队级变更列表；列表不提供放行、执行等高风险行内按钮，动作集中在详情。
- 列表：项目、环境、操作类型、目标、版本、状态、发起人、确认人、更新时间；筛选条件与分页写入 URL 并保留；空结果、无匹配、加载失败与只读分别呈现。
- 详情：标题区展示“目标 + 版本 + 状态”；属性区展示项目、环境、操作类型、执行方式、工作流、发起/确认/时间；正文区依次为变更范围、核对依据、恢复方案；时间线按时间升序，执行记录按尝试序号分列。
- 状态语义：待确认、已批准、执行中、待验证、已完成、失败、已取消；中断或超时显示“待核对”，不得显示为成功。
- 动作可用性：不可用时说明原因（如“计划已放行，修改需重新确认”“无权限”），不隐藏状态；放行、执行、验证、取消、重试均二次确认，确认文案写清环境、版本、范围与是否可撤销。
- 计划表单：桌面双列、窄屏单列；变更范围必须具体到本次版本/环境/资源，恢复方案为空禁止保存；操作类型非部署时隐藏服务与工作流字段，并说明本版不可执行。
- 产物与版本：验证通过后展示运行版本来源计划与验证时间；未验证的部署不显示为当前运行版本；未知版本显示“未知/待核对”。

## 代码变更与写能力入口（V0.4b）

- 项目代码页增加“代码变更”区块：列表显示基线、工作分支、校验结果、状态、PR 链接与创建时间；无权限时说明“未获得写能力授权”，不提供点击后报错的假入口。
- “发起代码变更”表单：仓库、基线分支/标签、工作分支、提交信息、补丁文件/粘贴、校验工作流；提交前校验补丁大小与分支名，服务端错误定位到字段。
- 失败保留补丁与已填字段；成功后进入排队态并展示运行链接；校验失败可查看差异与原因后重新发起。
- Bug 详情：创建远端 Issue 需选择仓库并填写标题/正文；成功后展示远端编号、来源平台与原平台链接；关闭远端 Issue 不改变本地状态。
- 评论：本地事项沿用既有讨论输入；远端评论需选择已关联记录，结果不回填本地讨论区。

## 表单弹窗模式（006）

- 结构：标题栏（标题 + 关闭）→ 可滚动字段区（分组：基本信息 / 负责人与协作人 / 附件）→ 固定底栏（取消 + 主操作）。
- 间距：分组 24px、组内 16px；控件高 36px、文本域 88–120px；桌面宽 720px，窄屏左右 16px。
- 状态：loading/empty/no-match/error/read-only/pending 必须齐全；只读时保留已填内容并说明原因。
- 参考实现：`features/requirements/ui/requirement-form.tsx`、`features/bugs/ui/bug-form.tsx`。
