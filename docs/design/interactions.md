# 交互规范

## 1. 状态矩阵

任何数据界面至少实现以下状态：

| 状态 | 表现 | 恢复 |
| --- | --- | --- |
| loading | 骨架屏或 PageLoading，布局尺寸稳定 | 自动 |
| success | 展示数据 | — |
| empty | 空状态 + 下一步操作 | 创建/邀请/清除筛选 |
| no-match | 区别于 empty，说明筛选无结果 | 清除筛选 |
| error | 可读说明 + requestId（如有）+ 重试 | 重试按钮 |
| read-only | 隐藏/禁用写操作，说明原因 | 联系管理员/切换角色 |
| pending action | 按钮 loading、禁用重复提交 | 成功/失败后恢复 |

## 2. 焦点与键盘

- 所有交互元素可通过 Tab 到达，焦点环可见。
- 对话框：打开后焦点进入内容，Tab 在内部循环，Esc 关闭，关闭后焦点回到触发元素。
- 下拉菜单：Enter/Space 打开，方向键移动，Esc 关闭。
- 表格行/卡片可点击时，必须有可聚焦的标题按钮或链接。
- 图标按钮必须有 `aria-label`。
- 不要在 `onClick` 中把非按钮元素伪装成按钮而不补键盘处理。

## 3. 异步与反馈

- 提交开始立即进入 pending，按钮禁用并显示进度文案。
- 成功：toast + 关闭弹窗/刷新列表；不要静默成功。
- 失败：保留输入，显示字段错误或页面级错误；可重试。
- 长列表/详情：加载失败保留已加载数据，提供局部重试。
- 避免重复 toast：一次操作只反馈一次。

## 4. 危险操作

- 删除、停用、关闭、取消、撤回、撤销授权必须二次确认。
- 确认文案说明对象、后果、是否可恢复。
- 需填写原因的操作（取消需求、关闭 Bug、撤回回归）原因必填并写入活动。
- 危险按钮使用 destructive 样式，默认焦点不要落在危险按钮上。

## 5. 权限与角色

- 浏览者/只读角色：隐藏写操作；若保留按钮则禁用并说明原因。
- 管理员专属：入口按角色隐藏；服务端必须再次校验。
- 最后管理员保护、资源归属等业务错误显示业务错误码对应的可读提示。
- 前端隐藏不能替代服务端鉴权。

## 6. 导航与 URL

- 列表筛选、分页、详情打开状态尽量写入 URL。
- 浏览器返回/刷新恢复筛选和详情。
- 详情关闭不丢失筛选；清除筛选有明确按钮。
- 页面切换时避免骨架闪烁：加载占位延迟 200ms 出现（统一使用 `DelayedLoading`），快速加载直接呈现内容；超过 200ms 才显示骨架或 PageLoading，慢加载仍有明确反馈。

## 7. 文案

- 使用简体中文、短句、动词开头。
- 错误说明“发生了什么 + 下一步”；不暴露内部异常。
- 状态使用业务语言：待处理、开发中、待测试、测试中、测试通过、已取消、待回归、已解决、已关闭。
- 空态标题说清“没有什么”，说明说清“可以做什么”。

## 8. 敏感值查看

- 凭据明文默认只显示固定掩码，任何页面不得默认展示明文。
- 查看明文必须先弹出二次确认框，要求输入当前登录密码；密码只用于本次校验，不写入状态持久化、URL 或日志。
- 弹窗打开后自动聚焦密码输入；提交中禁用按钮；密码错误保留弹窗并清空输入，显示可重试的说明；连续错误过多显示限流提示。
- 查看成功后关闭弹窗，在详情区临时展示明文并倒计时自动隐藏（默认 30 秒），提供“立即隐藏”；切换记录、关闭页面或组件卸载时立即清除。
- 明文不提供复制按钮、不进入剪贴板之外的持久存储；查看动作写入审计，审计只记录对象、版本、操作者与时间。
- API Token 身份不能完成明文查看；前端隐藏入口不能替代服务端鉴权。

## 9. 可访问性

- 文本与背景对比度满足 WCAG AA。
- 表单 label 与控件关联；错误用 `aria-describedby`/`role="alert"`。
- 图片有 alt；装饰图片 alt=""。
- 动效尊重 `prefers-reduced-motion`。
- 触控目标不小于 32×32px，移动端建议 44×44px。
